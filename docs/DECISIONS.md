# Журнал архітектурних рішень (ADR)

Формат: **рішення → причина → наслідки**. Запис додається, коли рішення впливає на структуру,
залежності або поведінку продукту. Історія робіт — у [`MEMORY.md`](MEMORY.md).

---

## ADR-001 — Стек: Electron + vanilla UI + PowerShell 5.1
**Рішення.** Оболонка — Electron (31.x), інтерфейс — чистий HTML/CSS/JS без бандлера,
системні операції — Windows PowerShell 5.1 (вбудований у Windows).
**Причина.** Потрібен GUI для Windows із доступом до реєстру/служб/DISM без встановлення залежностей
на цільових машинах; PowerShell 5.1 є в кожній Windows 10/11 «з коробки».
**Наслідки.** Немає кроку збірки фронтенду; скрипти можна читати й перевіряти окремо.
Обмеження: модель віджета Electron залежить від версії (див. ADR-002).

## ADR-002 — Electron запінено на 31.7.7
**Рішення.** Не оновлювати Electron до новіших мажорів.
**Причина.** Electron 44+ вимагає VC++ runtime, якого немає на цільових машинах
(аудиторія — старі/«занедбані» ПК без інсталяторів середовищ).
**Наслідки.** Частина відкритих у `npm audit` попереджень Electron залишається.
Пом'якшення — у [`SECURITY.md`](SECURITY.md) (відсутність віддаленого контенту, білий список IPC, CSP).
Перегляд рішення — коли зможемо постачати VC++ DLL разом із застосунком (див. `TECH-DEBT.md`, P1).

## ADR-003 — Undo-записи формують самі PowerShell-скрипти
**Рішення.** Кожен скрипт повертає `undo[]` зі «старими» значеннями; журнал — `restore.json`.
**Причина.** Лише скрипт знає, що саме він змінив і яким було попереднє значення.
**Наслідки.** Відкат не залежить від коду застосунку; контракт зафіксовано тестами
(`restore.ps1` мусить обробляти кожен `kind`).

## ADR-004 — Керування автозапуском через StartupApproved
**Рішення.** Вимикати/вмикати елементи автозапуску прапорцями `StartupApproved`, а не переміщенням ключів.
**Причина.** Той самий механізм, що використовує Task Manager; не руйнує записи програм.
**Наслідки.** Дії оборотні й передбачувані; стан видно в системних інструментах.

## ADR-005 — Консольні задачі у видимому вікні PowerShell
**Рішення.** SFC/DISM/chkdsk/WinSxS запускаються у видимому вікні; черга чекає його закриття.
**Причина.** Користувач має бачити прогрес і результат довгих системних операцій.
**Наслідки.** Черга «блокується» на час виконання — це очікувано й позначено в UI.

## ADR-006 — Живі метрики: CPU/RAM із Node, диски/SMART — PowerShell
**Рішення.** CPU/RAM/uptime беруться з `os` (без спавну процесів); диски й SMART — окремим PS-скриптом із кешем.
**Причина.** Дешева статистика щосекунди не має породжувати процеси; важкі запити — рідше.
**Наслідки.** Низьке навантаження на слабких ПК; дані про диски оновлюються з затримкою.

## ADR-007 — Скрипти передаються через `-EncodedCommand`
**Рішення.** Тіло `.ps1` кодується в Base64 (UTF-16LE) і передається як аргумент.
**Причина.** Працює й для файлів **усередині asar**, без розпакування й без проблем із кодуванням.
**Наслідки.** Один механізм запуску для dev і packaged-режиму.

## ADR-008 — Іконка та version info без native-залежностей
**Рішення.** ICO генерує `System.Drawing` (`tools/make-icon.ps1`), версію/іконку в exe вшиває `resedit` (чистий JS).
**Причина.** Уникаємо native-модулів і додаткових інсталяторів на машині збірки.
**Наслідки.** Збірка повторювана; версія exe = версія `package.json`.

## ADR-009 — «Порядок»: кошики на місці, ярлики сортуються, системні значки не чіпаються
**Рішення.** Папки створюються на робочому столі / всередині «Завантажень»; файли — за типами,
ярлики програм — окремо («Програми» / «Офісні програми»); ярлики на папки й сайти, системні значки й
файли молодші за 24 години в «Завантаженнях» — не чіпаються.
**Причина.** Люди хочуть лад у звичному місці, не втрачаючи системних елементів.
**Наслідки.** Поведінка зафіксована пісочницею (`npm run test:order`); кожне переміщення можна повернути.

## ADR-010 — Модель розповсюдження: безкоштовно для всіх
**Рішення.** Ліцензування, ключі, тріали й гейтинг задач прибрано; застосунок безкоштовний, з атрибуцією «Створено в ER7 Studio».
**Причина.** Позиція автора: подарунок користувачам.
**Наслідки.** Немає коду ліцензування та пов'язаної документації; EULA описана як безкоштовна.

## ADR-011 — Теми через CSS-змінні, типова — світла
**Рішення.** `:root` містить світлі значення, `body.theme-gray|black` перекривають змінні; `THEME_BG` у main задає фон вікна.
**Причина.** Уникнути «темного спалаху» при старті; нативні контроли мають відповідний `color-scheme`.
**Наслідки.** Додавання теми = один блок змінних; тема приходить у `i18n:get` і застосовується до важких IPC.

## ADR-012 — Структура репозиторію: `src/`, `site/`, `marketing/`, окрема автоматизація
**Рішення.** Код застосунку — `src/`; лендінг — `site/` (деплой на Vercel); контент соцмереж — `marketing/`;
скрипти публікації Instagram — `marketing/instagram/automation/` як **окремий мініпроєкт** із власним `package.json`.
**Причина.** Різні залежності (застосунок: Electron/packager; автоматизація: playwright-core) і різні цикли життя.
**Наслідки.** `npm ci` у корені не тягне Playwright; asar не містить `marketing/`.

## ADR-013 — Generated-артефакти поза git
**Рішення.** `node_modules/`, `release/`, `dist/`, `.vercel/`, `automation/data|state/`, логи й тимчасові файли — у `.gitignore`.
**Причина.** Відтворюваність репозиторію, менший розмір, відсутність секретів у git.
**Наслідки.** Релізні архіви перезбираються командою; у репозиторії — лише джерело.
