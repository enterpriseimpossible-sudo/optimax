# Безпека — модель, секрети, ризики

> Як повідомити про вразливість — див. [`../SECURITY.md`](../SECURITY.md).
> Цей документ описує **внутрішню** модель безпеки проєкту та відомі ризики.

## 1. Модель довіри

OptiMax — локальний десктопний застосунок для Windows, який свідомо **змінює системні налаштування**
(реєстр, служби, плани живлення, мережа, файли) і тому працює з правами адміністратора.

| Припущення | Наслідок |
|---|---|
| Користувач свідомо запускає застосунок від адміністратора | задачі виконуються з повними правами; кожна зміна має бути оборотною |
| Застосунок не спілкується з мережею | немає телеметрії, акаунтів, оновлень «ззовні» |
| Файли застосунку не змінюються сторонніми особами | цілісність asar не є межею безпеки (див. ризики) |
| Скрипти постачаються разом із застосунком | ланцюг постачання = репозиторій + збірка на довіреній машині |

## 2. Що вже захищено

- **Ізоляція renderer'а:** `contextIsolation: true`, `nodeIntegration: false`; доступ лише через `preload`.
- **Білий список IPC:** 20 каналів у `src/preload.js`; усе інше відхиляється (`app.js` не може викликати довільний IPC).
- **Обмежене відкриття зовнішніх адрес:** `ALLOWED_OPEN` у `src/main.js` — лише `ms-settings:*`.
- **CSP сторінки:** `default-src 'none'; script-src 'self' file:; connect-src 'none'` — жодних зовнішніх запитів чи скриптів.
- **Немає віддаленого контенту:** UI завантажується з `file://`; сторонні сторінки не вбудовуються.
- **Відсутність телеметрії та мережевих запитів** — перевіряється відсутністю мережевих викликів у коді.
- **Оборотність змін:** кожна зміна фіксується undo-записом і повертається через `restore.ps1` (це також межа безпеки: невдала/небажана дія не є незворотною).
- **Ізольована пісочниця** для перевірки файлових задач (`tools/test-order.js`, тека `C:\Temp\opencode\order-sandbox`).

## 3. Секрети та локальні дані

| Що | Де | Статус |
|---|---|---|
| Сесія Instagram (cookies) | `marketing/instagram/automation/state/auth.json` | **у .gitignore** — у репозиторій не потрапляє |
| Токен Vercel (OIDC) | `site/.env.local` | **у `site/.gitignore`** (`.env*`) |
| Налаштування користувача, журнал відкатів, логи | `%APPDATA%\OptiMax\` | поза репозиторієм, локально |

Правила:

1. Секрети **не комітяться**: перевірено (`git check-ignore` для обох файлів) і перевірено історію git на шаблони токенів — чисто.
2. Секрети не потрапляють у збірку: `release/` та `dist/` створюються лише з `src/`, `assets/`, `package.json` (asar містить тільки застосунок; `site/`, `docs/`, `tests/`, `tools/` виключені).
3. Логи не містять персональних даних — лише назви задач, повідомлення скриптів і обсяги.
4. Якщо секрет усе-таки виплив: **ротація** (перевипуск сесії/токена), потім — за потреби — очищення історії з попередженням про наслідки (force-push переписує історію для всіх).
5. Передача секретів — лише через захищений канал; у документації згадуються тільки **назви** файлів/змінних.

## 4. Ризики третіх сторін (стан 2026-10-16)

`npm audit --omit=dev` → **0 вразливостей** (у застосунку немає runtime-залежностей).
Повний `npm audit` (разом із build-time залежностями) → 6 записів: 2 high, 4 moderate, 0 critical.

| Пакет | Рівень | Суть | Застосовність / рішення |
|---|---|---|---|
| `electron` ≤ 41.10.5 | high | ASAR Integrity Bypass; Service worker може підробити відповіді `executeJavaScript`; AppleScript-ін'єкція (macOS) | ASAR не є нашою межею безпеки; віддаленого контенту й service worker'ів немає; збірка лише Windows x64 (AppleScript не застосовний). **Оновлення Electron свідомо відкладене** (див. ADR-002) |
| `extract-zip` | high | path traversal через symlink під час розпакування архівів | Використовується **лише під час збірки** `@electron/packager` для розпакування офіційного Electron-архіву (HTTPS, electron release CDN). Не входить у продукт |
| `@electron/get` → `global-agent` → `roarr` → `sprintf-js` | moderate | DoS через необмежену точність формату | Build-time; вплив лише на машину збірки |

**Дія за планом:** оцінити оновлення `@electron/packager`/`extract-zip` (збіркові) окремо від Electron;
оновлення самого Electron — лише разом із планом доставки VC++ runtime на цільові машини
(див. [`TECH-DEBT.md`](TECH-DEBT.md), P1).

## 5. Що перевірити перед публікацією

```powershell
git status --porcelain            # немає випадкових нових файлів
git check-ignore -v marketing/instagram/automation/state/auth.json site/.env.local
npm run verify                    # тести + цілісність UI + JS-гейт + PowerShell
npm run package                   # збірка; переконатись, що asar містить лише src/, assets/, package.json
```

Перед `git push`: переконайтеся, що в коміт не потрапили `state/`, `.env*`, `release/`, `dist/`, `node_modules/`.
