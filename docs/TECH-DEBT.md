## P1 — попередження Electron у `npm audit`

**Суть.** `electron ≤ 41.10.5` (у нас 31.7.7) має 3 відкриті попередження (ASAR integrity bypass,
spoofing відповідей `executeJavaScript` через service worker, AppleScript-ін'єкція на macOS),
плюс build-time `extract-zip` (path traversal) і транзитивні moderate-залежності `@electron/get`.

**Чому не виправлено зараз.** Оновлення Electron ламає підтримку машин без VC++ runtime — це
свідоме рішення (ADR-002) і саме та аудиторія, для якої продукт створено.

**Пом'якшення (уже діють).** Немає віддаленого контенту; CSP `default-src 'none'`/`connect-src 'none'`;
service worker'и не реєструються; білий список IPC; `contextIsolation`; збірка лише Windows x64.

**План.** (1) Оцінити оновлення збіркових пакетів (`@electron/packager`, `extract-zip`) окремо від Electron.
(2) Коли зʼявиться механізм доставки VC++ DLL разом із застосунком — перевірити застосунок на новому Electron
і оновити ADR-002.

## P2 — суттєве

1. **Немає e2e-перевірки Electron-вікна** (реальний preload + IPC). Smoke-тест працює в мок-режимі;
   *план:* `@playwright/test` + Electron-драйвер або розширення `tests/smoke/main.js` стабом preload.
2. **CI не запускає пісочницю «Порядку».** `npm run test:order` поки лише локально.
   *План:* додати крок у CI (windows-runner має PowerShell; потрібна лише тека `C:\Temp\opencode`).
3. **`npm run test:ui` у CI.** Локально проходить; на GitHub windows-runner Electron зазвичай працює,
   але це не перевірено на живому runner'і. *План:* переконатися після першого push; за потреби — винести крок окремо.

## P3 — покращення

1. **Документація плоскою структурою.** Для поточного обсягу це ок (додано покажчик `docs/README.md`);
   за потреби — підпапки `architecture/`, `development/`, `decisions/`.
3. **Вага маркетингових PNG.** `site/preview-desktop.png` (2 МБ) і `marketing/**` (~16 МБ).
   *План:* за потреби — WebP для прев'ю, а важкі вихідники тримати поза репозиторієм.
4. **`tools/*` друкують у консоль** (це dev-інструменти, тому `console.log` там доречний; `check-js` забороняє його лише в `src/`).

## P4 — косметика

1. Єдині назви файлів маркетингу (`post-01`, `stories-01`, `story-0N`, `slide-0N`) — можна звести до однієї схеми.
2. `docs/screens/` містить і старі скріншоти реальних прогонів (темна тема) — історично цінні, але виглядають інакше за поточний UI.

## Перевірено й визнано OK (щоб не перевіряти повторно)

- У `src/` немає `console.log`, `TODO/FIXME`, неявної рівності (`==`), `var`.
- Локалі: 5 мов × 270 ключів, повний паритет (перевіряє `check:ui`).
- Секрети: `automation/state/auth.json` і `site/.env.local` — у `.gitignore`; в історії git токенів немає.
- Заблоковані шляхи: `node_modules/`, `release/`, `dist/`, `.vercel/`, логи, `*.lnk`.
- `@electron/packager` і `electron` — єдині devDependencies; зайвих пакетів немає (`npm audit --omit=dev` → 0).
