# Тестування та перевірки

## 1. Команди

| Команда | Що робить | Час |
|---|---|---|
| `npm test` | юніт-тести `node:test`: каталог задач, контракт скриптів, store, i18n | ~0.3 с |
| `npm run check:ui` | цілісність локалей (5 мов × 270 ключів), ключі з коду/HTML, `id` елементів | ~0.2 с |
| `npm run check:js` | синтаксис усіх JS (`node --check`), заборонені `console.log` у `src/`, маркери конфліктів, валідність JSON | ~1 с |
| `npm run check:ps` | синтаксис усіх 39 PowerShell-скриптів | ~2 с |
| `npm run verify` | усе перелічене вище послідовно (використовується в CI) | ~4 с |
| `npm run test:order` | пісочниця «Порядку»: переміщення файлів і ярликів + undo round-trip | ~30 с |
| `node tools/run-task.js <taskId>` | реальний прогін однієї задачі з undo та логом (як у застосунку) | залежить |
| `npm run mock` | UI у браузері (мок-API) — ручна перевірка інтерфейсу | — |
| `npm run package` | збірка portable-версії (перевірка, що реліз збирається) | ~2 хв |

## 2. Покриття

**Автоматично перевіряється:**

1. **Каталог задач** — унікальність `id`, обов'язкові поля, наявність текстів (uk) для кожної задачі,
   існування файлів скриптів і контракт результату (`Emit-Result` / `Read-Host` для консольних).
2. **Профілі** — посилаються лише на реальні задачі, кожен має ≥3 задачі.
3. **Undo-контракт** — усі `kind` обробляються `restore.ps1`.
4. **Store** — merge налаштувань, журнал undo (append/remove/clear), логи, стійкість до пошкоджених файлів, скидання.
5. **i18n** — повнота словників відносно `uk`, локалізація каталогу, підстановка параметрів, фолбек, формати часу.
6. **Цілісність UI** — кожен ключ, використаний у коді/HTML, існує в словниках; кожен `id`, який шукає `app.js`, є в `index.html`.
7. **Синтаксис** — JS і PowerShell.
8. **«Порядок» у пісочниці** — реальні переміщення у `C:\Temp\opencode\order-sandbox` + повернення через `restore.ps1`.

**Перевіряється вручну (є команди/інструкції):**

- реальні прогони задач (`tools/run-task.js`), зокрема реєстровий undo round-trip;
- UI у мок-режимі та в зібраному застосунку (теми, мови, налаштування);
- димовий запуск `release\OptiMax-win32-x64\OptiMax.exe` (4 процеси → коректне завершення);
- рендери маркетингу (`marketing/instagram/tools/render-*.js`).

## 5. Як додати тест

1. Створіть `tests/<назва>.test.js` на базі `node:test` + `node:assert`.
2. Додайте файл у список `npm test` (рядок `node --test …`) або в `--test`-маску.
3. Не використовуйте мережу й реальні системні зміни — тільки тимчасові теки (`fs.mkdtempSync`).
4. Для файлових задач — додавайте кейс у `tools/test-order.js` (пісочниця сама прибирає за собою).
